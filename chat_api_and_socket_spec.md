# Chat System & WebSocket Specification (Group & Direct)

This specification defines the complete backend architecture, REST API endpoints, WebSocket protocol, database schema, and AI assistant integration for both **Direct (1-on-1)** and **Group (Project-based)** chats in the mobile application.

---

## 2. Database Schema (Entities & Relationships)

### 2.1 `Conversation`
Represents a chat thread (either 1-on-1 direct or multi-party project group).

| Field | Type | Nullable | Description |
| :--- | :--- | :---: | :--- |
| `id` | `BigInt` (PK) | No | Unique conversation ID. |
| `project_id` | `BigInt` (FK) | Yes | Required for group chat. Links to `Project`. Null for pure direct chats. |
| `is_group` | `Boolean` | No | `true` for group chat, `false` for direct 1-on-1. |
| `name` | `Varchar(255)` | No | Conversation display name (e.g. `"Downtown Tech Hub \|\| Group Chat"` or investor name). |
| `avatar_url` | `Varchar(512)` | Yes | Optional custom group avatar or investor photo URL. |
| `created_by_id` | `BigInt` (FK) | No | User ID who initiated the conversation. |
| `last_message_id`| `BigInt` (FK) | Yes | Pointer to latest message for fast ordering and preview. |
| `created_at` | `DateTime` | No | ISO timestamp. |
| `updated_at` | `DateTime` | No | Updated whenever a new message is received. |

---

### 2.2 `ConversationParticipant`
Tracks membership, roles, and unread counts for each user in a conversation.

| Field | Type | Nullable | Description |
| :--- | :--- | :---: | :--- |
| `id` | `BigInt` (PK) | No | Primary key. |
| `conversation_id`| `BigInt` (FK) | No | Links to `Conversation`. |
| `user_id` | `BigInt` (FK) | No | Links to `User`. |
| `role` | `Varchar(32)` | No | `"SPONSOR"`, `"INVESTOR"`, `"AI"`, `"MODERATOR"`. |
| `is_admin` | `Boolean` | No | `true` if sponsor / group owner. |
| `last_read_message_id` | `BigInt` (FK) | Yes | Highest message ID read by this participant. |
| `unread_count` | `Integer` | No | Default `0`. Increments on unread incoming messages. |
| `joined_at` | `DateTime` | No | When user entered group. |
| `is_active` | `Boolean` | No | `false` if removed by sponsor or left group. |

---

### 2.3 `ChatMessage`
Individual chat messages supporting text, images, and voice recordings.

| Field | Type | Nullable | Description |
| :--- | :--- | :---: | :--- |
| `id` | `BigInt` (PK) | No | Unique message ID. |
| `conversation_id`| `BigInt` (FK) | No | Target conversation. |
| `sender_id` | `BigInt` (FK) | Yes | Null if sent by automated AI system. |
| `is_ai` | `Boolean` | No | `true` if generated by AI assistant (VentureAI / Damani AI). |
| `sender_role` | `Varchar(32)` | No | `"Sponsor"`, `"Investor"`, `"AI"`, `"System"`. |
| `message_type` | `Varchar(16)` | No | `"text"`, `"image"`, `"voice"`, `"system"`. |
| `text` | `Text` | No | Message content or system notice text. |
| `media_url` | `Varchar(512)` | Yes | S3 / CDN URL for image or audio file. |
| `voice_duration` | `Varchar(16)` | Yes | Duration string for voice notes (e.g. `"0:34"`). |
| `created_at` | `DateTime` | No | ISO timestamp with timezone. |
| `is_deleted` | `Boolean` | No | Soft-delete flag (default `false`). |

---

### 2.4 `AiSuggestion`
Automated actionable tips generated by the AI for the project sponsor/investors.

| Field | Type | Nullable | Description |
| :--- | :--- | :---: | :--- |
| `id` | `Varchar(64)` | No | Unique string ID (e.g. `"sugg_1"`). |
| `conversation_id`| `BigInt` (FK) | No | Associated group chat. |
| `title` | `Varchar(255)` | No | Tip text (e.g. `"Share retention rate with David"`). |
| `icon` | `Varchar(64)` | No | UI icon identifier (e.g. `"lightbulb"`, `"trending_up"`). |
| `is_completed` | `Boolean` | No | Marked `true` once action is performed. |
| `created_at` | `DateTime` | No | Creation timestamp. |

## 3. REST API Specification

All REST requests require `Authorization: Bearer <access_token>`.

### 3.1 Start / Retrieve Conversation
Initiates or returns an existing conversation.

- **Endpoint**: `POST /api/v1/notifications/chat/conversations/start/`
- **Request Body**:
```json
{
  "target_user_id": 10,
  "project_id": 3
}
```
> **Rules:**
> 1. If `project_id > 0` and `target_user_id == 0`, get or create the project's **Group Chat** (`is_group = true`).
> 2. If `target_user_id > 0` and `project_id == 0` (or `> 0`), get or create the **Direct 1-on-1 Chat** (`is_group = false`) between the authenticated user and `target_user_id`.

- **Success Response (`200 OK` / `201 Created`)**:
```json
{
  "status": "success",
  "data": {
    "id": 1,
    "project": 3,
    "is_group": true,
    "name": "Downtown Tech Hub || Group Chat",
    "last_message": "Hello Arif! Very interested to hear about your project.",
    "unread_count": 0,
    "updated_at": "2026-09-30T09:40:00.000000Z"
  }
}
```

### 3.4 Upload Media Attachment (Image / Voice Note)
Uploads an image or recorded audio file to receive a public URL before sending a message.

- **Endpoint**: `POST /api/v1/notifications/chat/upload/`
- **Content-Type**: `multipart/form-data`
- **Form Fields**:
  - `file`: `Binary file` (JPG, PNG, WebP, MP4, M4A, MP3, AAC)
  - `type`: `string` (`"image"` or `"voice"`)
  - `voice_duration`: `string` (e.g. `"0:42"`, only for voice notes)

- **Success Response (`201 Created`)**:
```json
{
  "status": "success",
  "data": {
    "media_url": "https://storage.example.com/chat/media/voice_83921.m4a",
    "type": "voice",
    "voice_duration": "0:42"
  }
}
```

---

### 3.5 Mark Conversation as Read
Resets the authenticated user's `unread_count` for this conversation.

- **Endpoint**: `POST /api/v1/notifications/chat/conversations/{conversation_id}/read/`
- **Request Body**: `{}`
- **Success Response (`200 OK`)**:
```json
{
  "status": "success",
  "message": "Conversation marked as read"
}
```

---

### 3.6 Remove Participant (Sponsor Only)
Allows project sponsors to remove a member from a group chat.

- **Endpoint**: `DELETE /api/v1/notifications/chat/conversations/{conversation_id}/participants/{user_id}/`
- **Success Response (`200 OK`)**:
```json
{
  "status": "success",
  "message": "Participant removed successfully"
}
```
*(Backend also broadcasts a system message and a `participant_removed` WebSocket event).*

## 4. WebSocket Architecture & Protocols

Real-time messaging, typing indicators, read receipts, and AI suggestions are powered by WebSocket connections.

### 4.1 Connection URL & Authentication
- **URL**: `wss://<api-domain>/ws/chat/{conversation_id}/?token=<jwt_access_token>`
- **Handshake Protocol**:
  1. Server inspects `token` query parameter or `Authorization` header during handshake.
  2. If token is invalid or user is not a participant in `{conversation_id}`, close connection immediately with status code `4003 Forbidden`.
  3. On success, user is subscribed to Redis channel layer group `chat_<conversation_id>`.

---

### 4.2 Heartbeat (Ping / Pong)
To maintain active connections through load balancers and detect disconnected clients:
- Client sends: `{"type": "ping"}` every 30 seconds.
- Server responds: `{"type": "pong"}`.

---

### 4.3 Client-to-Server Events

#### Event: `send_message`
Sends a new message to the conversation.

```json
{
  "type": "send_message",
  "message_type": "text",
  "text": "Here is our updated financial forecast.",
  "media_url": null,
  "voice_duration": null
}
```

Media upload payload example:
```json
{
  "type": "send_message",
  "message_type": "image",
  "text": "Cap table overview screenshot",
  "media_url": "https://storage.example.com/chat/images/cap_table.png",
  "voice_duration": null
}
```

#### Event: `typing`
Signals typing state.

```json
{
  "type": "typing",
  "is_typing": true
}
```

#### Event: `mark_read`
Acknowledge receipt of messages up to a specific ID.

```json
{
  "type": "mark_read",
  "last_message_id": 103
}
```

```json
    "voice_duration": null,
    "created_at": "2026-09-30T09:03:00Z"
  }
```

#### Event: `user_typing`
Notifies that another user is typing.

```json
{
  "type": "user_typing",
  "user_id": 8,
  "user_name": "David Chen",
  "is_typing": true
}
```

#### Event: `messages_read`
Informs sender that their message was read.

```json
{
  "type": "messages_read",
  "conversation_id": 1,
  "reader_id": 8,
  "reader_name": "David Chen",
  "last_read_message_id": 104
}
```

#### Event: `ai_suggestion`
Broadcast when the AI assistant generates contextual tips for the sponsor.

```json
{
  "type": "ai_suggestion",
  "suggestions": [
    {
      "id": "sugg_1",
```

Broadcast when a user leaves or is kicked from group.

```json
  "user_name": "David Chen",
```

## 5. AI Assistant (VentureAI) Architecture in Group Chats

In project group chats, the AI serves as an active assistant to help sponsors close funding deals:

1. **Triggering Conditions**:
   - Explicit invocation: When a user @mentions the AI or asks questions directed at `@VentureAI`.
   - Silent Listener: After every 3-5 investor questions, the AI generates background **suggestions** (`ai_suggestion` event) visible to the sponsor.
   - Welcome Bot: Automatically generates the opening greeting when the group chat is first started.
2. **Context Window Injection**:
   The AI agent receives:
   - Project pitch & metrics (`funding_goal`, `raised_amount`, `target_roi`, `hold_period_months`, `timeline_months`, `industry`).
   - Recent 10 chat messages for immediate conversational context.
3. **Guardrails**:
   - The AI must never promise financial returns or guarantee investment safety.
   - Tone must remain objective, supportive, and professional.

## 6. Error Codes & HTTP Status Mapping

| HTTP Code | Error Code | Description |
| :--- | :--- | :--- |
| `400 Bad Request` | `INVALID_PAYLOAD` | Missing required fields (`project_id` or `target_user_id`). |
| `401 Unauthorized`| `UNAUTHORIZED` | Token missing or expired. |
| `403 Forbidden` | `NOT_PARTICIPANT` | User is not allowed in this conversation. |
| `403 Forbidden` | `NDA_REQUIRED` | Investor has not signed NDA for confidential project group chat. |
| `404 Not Found` | `CONVERSATION_NOT_FOUND` | Conversation ID does not exist. |
| `413 Payload Too Large` | `FILE_TOO_LARGE` | Media file exceeds 25 MB limit. |
